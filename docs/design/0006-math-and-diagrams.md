# Math and Diagrams

**Goal:** Render LaTeX math and Mermaid diagrams inside notes without weakening
the app's rendering or security model. Math is rendered in Go with KaTeX so the
preview needs only the KaTeX stylesheet. Mermaid diagrams are rendered in the
webview by a lazily loaded client library because Mermaid is JavaScript-only.

**Architecture:** `markdown.go` adds `goldmark-katex` to the shared goldmark
instance, so `$…$` and `$$…$$` become KaTeX HTML for the preview, exported HTML,
and print. Mermaid fenced blocks are deliberately left as normal code blocks by
the Go renderer; `frontend/src/main.ts` finds `code.language-mermaid` inside the
preview, dynamically imports `mermaid`, renders each block to SVG, and replaces
the `<pre>` with a `.mermaid-block`. Toolbar buttons insert the syntax. The
KaTeX CSS is imported once at the frontend entry point.

**Tech Stack:** Go 1.26, goldmark, `github.com/FurqanSoftware/goldmark-katex`,
KaTeX (`katex/dist/katex.min.css`), Mermaid 12 (dynamically imported), plain
TypeScript and CSS.

**Spec:** this document. It is retrospective: it records the behavior shipped
in `ca0bd10` and the constraints later rendering, export, print, and external
change work must preserve.

## Global Constraints

- **Math is Go-side HTML.** The goldmark KaTeX extension renders delimiters into
  KaTeX markup. The frontend does not parse `$…$` and does not ship the KaTeX
  JavaScript runtime; it only imports the stylesheet.
- **KaTeX must parse before Markdown.** The extender is added to the goldmark
  instance so formulas are protected from Markdown processing. Underscores,
  asterisks, backslashes, and line breaks inside math must not be interpreted as
  emphasis or list syntax.
- **Mermaid is client-side and lazy.** `import("mermaid")` happens only when a
  note actually contains a Mermaid block. A note without diagrams does not pay
  the bundle cost on first paint.
- **Mermaid runs with `securityLevel: "strict"`.** Note content is untrusted
  input. Labels must not execute scripts or follow arbitrary links. The renderer
  is configured with `startOnLoad: false` and `suppressErrorRendering: true` so
  only the explicit render call produces output.
- **A diagram error is local.** A malformed diagram becomes a visible
  `.mermaid-block.is-error` message in place of that block. It does not fail the
  Markdown render, blank the preview, or affect other blocks.
- **No new storage format.** Math and diagrams live in ordinary Markdown. There
  is no sidecar, no attachment directory, and no binary asset.
- **Export and print keep math.** Exported HTML reuses the goldmark output, so
  KaTeX markup is present. The export template must include the KaTeX stylesheet
  for formulas to look correct; Mermaid diagrams are not serialized as SVG in
  exports because they are rendered by the live webview.
- **Raw HTML stays disabled.** Neither feature re-enables goldmark's unsafe
  mode. KaTeX output is generated by a trusted renderer from user input; Mermaid
  output is inserted only through the library's strict rendering path.

## Review Focus

1. **Formula syntax inside Markdown.** Inline math is `$E = mc^2$`; display math
   is `$$\frac{a}{b}$$`. A literal dollar sign can be escaped as `\$`. Because
   parsing happens before Markdown, a formula containing `*` or `_` is not
   turned into emphasis.
2. **KaTeX CSS is global, KaTeX JS is not.** Importing `katex/dist/katex.min.css`
   in `main.ts` styles every preview and the tooltip-free output. There is no
   runtime hydration step; if the HTML is present, it is already typeset.
3. **Mermaid dynamic import failure.** If the chunk cannot load (offline dev
   server, corrupted build), every pending block is replaced with a readable
   "Diagram error: …" wrapper rather than leaving a raw code block that looks
   like a bug.
4. **Stale previews.** Rendering is asynchronous. `renderMermaidBlocks` receives
   an `isStale` callback from `decoratePreview`; after each `await` it checks the
   preview sequence token and stops. An older render cannot overwrite a newer
   one.
5. **Unique render IDs.** Mermaid requires a unique element ID per render.
   `mermaidSeq` is incremented for every block (`mermaid-1`, `mermaid-2`, …),
   independent of note IDs, so repeated renders never collide.
6. **The raw fence survives Go rendering.** `TestRenderMermaidFenceStaysForClient`
   pins that `language-mermaid` and the diagram source are present in the HTML.
   This is the contract between the Go renderer and the client decorator.
7. **Print behavior.** Math prints using the same KaTeX HTML and CSS. Mermaid
   diagrams that have rendered in the live preview are SVGs in the DOM and print
   as part of the preview; generated standalone exports do not contain them.

## 1. Problem and outcomes

Notes frequently contain technical writing: equations, sequence diagrams, and
flowcharts. Before this work, formulas appeared as literal dollar signs and
Mermaid fences appeared as syntax-highlighted code. Copying the diagram source
into an external renderer broke the writing flow.

After this work:

- Inline and display LaTeX render in the live preview, Read mode, and print.
- A ` ```mermaid ` fence renders as an SVG diagram in the preview.
- Toolbar buttons insert inline math, display math, and a starter Mermaid block.
- A malformed formula or diagram reports an error in place and leaves the rest
  of the note intact.
- Notes remain plain Markdown; no note-specific metadata or binary assets are
  introduced.

### Non-goals

- A visual equation or diagram editor.
- Server-side Mermaid rendering (no headless browser).
- Diagram export as standalone SVG/PNG, or embedding rendered Mermaid SVGs into
  Markdown/HTML exports.
- Rendering math in the editor textarea. The source stays literal Markdown.
- Supporting every MathJax macro. KaTeX's supported subset is the contract.

## 2. Math pipeline

`markdown.go` adds the extender:

```go
var markdownRenderer = goldmark.New(
    goldmark.WithExtensions(
        extension.GFM,
        extension.Footnote,
        extension.Typographer,
        highlighting.NewHighlighting(
            highlighting.WithStyle("github-dark"),
        ),
        &katex.Extender{},
    ),
    goldmark.WithParserOptions(parser.WithAutoHeadingID()),
)
```

The order matters: the KaTeX extender registers inline and block parsers that
recognize math delimiters before the normal Markdown inline parser consumes the
characters. The result is HTML containing KaTeX's `.katex` /
`.katex-display` spans and MathML, not a placeholder for a client renderer.

The frontend imports the stylesheet once:

```ts
import "katex/dist/katex.min.css";
```

Because the built frontend is embedded in the Wails binary, KaTeX fonts are
served from the same asset bundle. There is no CDN dependency and no network
access while rendering.

Consequences:

- `Render`, HTML export, and print all get the same typeset HTML.
- No client-side KaTeX runtime is needed; this keeps the preview render a pure
  Go call even though the visual result is rich.
- KaTeX output is display HTML generated from the user's math source. It is
  trusted renderer output, but it is not raw HTML from the note; the app still
  does not enable unsafe goldmark HTML.

## 3. Mermaid pipeline

Mermaid is JavaScript-only, so it runs in the webview:

```text
Go renderMarkdown
  └─ ```mermaid fence stays as <pre><code class="language-mermaid">…</code></pre>
        │
        ▼
renderPreview → preview.innerHTML → decoratePreview
        │
        ▼
renderMermaidBlocks(preview, isStale)
  ├─ querySelectorAll("pre > code.language-mermaid")
  ├─ loadMermaid()  ← dynamic import, first diagram only
  ├─ for each block: mermaid.render("mermaid-N", source)
  └─ replace <pre> with <div class="mermaid-block">SVG</div>
```

`loadMermaid()` caches the module promise, so concurrent previews share one
import. Initialization is:

```ts
mermaid.initialize({
    startOnLoad: false,
    securityLevel: "strict",
    suppressErrorRendering: true,
    theme: "dark",
    darkMode: true,
    fontFamily: "inherit",
    themeVariables: {
        background: "transparent",
        primaryColor: "#1a222d",
        primaryTextColor: "#dbe3ee",
        primaryBorderColor: "#2c3642",
        lineColor: "#8b97a8",
        secondaryColor: "#202a36",
        tertiaryColor: "#141a22",
        fontSize: "14px",
    },
});
```

The theme variables match the app's CSS palette so diagrams do not look like a
foreign widget. `securityLevel: "strict"` is the security boundary for labels
and links.

Each block is replaced before rendering, so an error or a stale render leaves a
visible wrapper rather than a missing node. The wrapper carries either the SVG
or `Diagram error: …`. `isStale()` is checked after the dynamic import and after
each render; a newer preview aborts the old loop.

The lazy import keeps Mermaid out of the initial path for notes without
diagrams. The production build may emit a separate chunk; that is expected and
is not a regression in startup behavior for ordinary notes.

## 4. Toolbar and authoring

`frontend/index.html` adds three buttons to the Markdown toolbar:

| Action | Insertion |
| --- | --- |
| `math` | Wraps the selection in `$…$`, defaulting to `E = mc^2`. |
| `mathblock` | Inserts a display block: `$$\n\\frac{a}{b}\n$$`. |
| `mermaid` | Inserts a starter fence: ` ```mermaid\nflowchart LR\n  A[Start] --> B[End]\n``` `. |

They use the same selection-preserving helpers as the other formatting actions
(`wrapSelection`, `insertBlock`) and return focus to the editor. The toolbar
scrolls horizontally at narrow widths (`0004`) rather than wrapping.

## 5. Styling, export, and print

`style.css` adds:

- `.katex` and `.katex-display` sizing/spacing within `.markdown-body`.
- `.mermaid-block` as a centered, overflow-x-auto container with a subtle
  background and border.
- `.mermaid-block svg` constrained to the content width and `height: auto`.
- `.mermaid-block.is-error` using the danger color and normal text wrapping.

Export and print reuse the Go HTML. KaTeX markup and fonts are styled when the
KaTeX stylesheet is present. The export template includes the app's own styles
and the KaTeX stylesheet so formulas do not collapse into plain text. Mermaid is
different: the exported HTML has no client-side Mermaid runtime, so a Mermaid
fence remains a code block there. This is an explicit scope boundary, not a
silent failure — the live preview is the diagram view.

## 6. Failure handling

| Situation | Behavior |
| --- | --- |
| Malformed LaTeX | KaTeX renders an inline error node in place of the formula; the rest of the Markdown still renders. |
| Unsupported macro | KaTeX reports the unsupported command visually; rendering continues. |
| Literal `$` intended | Escape as `\$`; an unmatched delimiter remains text. |
| Mermaid chunk fails to load | Each block becomes `.mermaid-block.is-error` with "Diagram error: …". |
| Invalid Mermaid syntax | `mermaid.render` throws; that block becomes an error wrapper. Other blocks continue. |
| Preview becomes stale mid-render | `isStale()` aborts after the import and after each block; no old SVG is written into the new preview. |
| Mermaid render ID collision | Avoided with a monotonically increasing `mermaidSeq`; each block gets a unique ID. |
| Print before Mermaid finishes | The preview may still show a code block or an empty wrapper; printing is a live snapshot. Wait for the diagram before printing. |
| Export of a Mermaid note | The fence is exported as Markdown/code; no SVG is embedded. Math is exported as KaTeX HTML. |
| Raw HTML in a diagram label | Blocked by Mermaid strict security; no script execution. |

## 7. Testing

Go tests pin the rendering contract:

| Test | What it pins |
| --- | --- |
| `TestRenderMathWithKaTeX` | `class="katex"`, `class="katex-display"`, and `<mfrac` appear for inline and display math. |
| `TestRenderMermaidFenceStaysForClient` | A Mermaid fence is emitted as `language-mermaid` code containing the source, ready for client decoration. |
| `TestRenderOmitsRawHTML` | Adding renderers did not weaken the raw-HTML boundary. |
| `TestRenderMarkdownExtensions` | GFM, task lists, and highlighting still work with the math extender present. |

Frontend checks are `npm --prefix frontend run typecheck`,
`npm --prefix frontend run build`, and `wails3 build`. Manual checks:

1. Inline and display formulas render in Split and Read modes.
2. A formula containing `*`, `_`, and line breaks is not mangled by Markdown.
3. A Mermaid flowchart renders; the source fence disappears from the preview.
4. Two diagrams on one page both render with distinct IDs.
5. A malformed diagram shows an error wrapper and the rest of the note remains.
6. A note with no diagrams does not load the Mermaid chunk on first paint
   (verify in the browser/network panel during development).
7. Print preview and HTML export show typeset math.
8. Switching notes quickly does not leave an old diagram in the new preview.
